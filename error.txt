# CỨU DỮ LIỆU PAPER TRADING — CHẠY Ở LAPTOP CÓ `wrangler login`

Viết ngày 2026-09-25. Laptop kia (Allianz) bị firewall chặn `wrangler login`,
nên mọi việc cần xác thực Cloudflare phải làm ở máy này.

Đã kiểm trước ở laptop Allianz: `npm run build` xanh (ra đủ `dist/`) và test lõi
**602 passed / 44 file**. Bên đây không phải sửa code — chỉ login + deploy.

Nội dung cũ của file này (prompt phân tích case study) đã được chuyển sang
`case-study-prompt.txt`, không mất.


## 0. Chuẩn bị

    git clone https://github.com/tuanhpham/lux-lookthrough.git   # hoặc: git pull
    cd lux-lookthrough/screener-ts
    node -v            # phải >= 20
    npm install
    npx wrangler login # ← đúng cái bước laptop Allianz bị chặn
    npx wrangler whoami

`database_id` (af468661-bfed-409e-8df8-34ecf8cda199) đã nằm sẵn trong
`apps/desktop/wrangler.toml`, không phải dán lại.


## 1. Sao lưu TRƯỚC khi chạm vào gì (đừng bỏ bước này)

    cd apps/desktop
    npx wrangler d1 export screener-sync --remote --output=./d1-backup-2026-09-25.sql

Và mở app trên MỌI thiết bị còn giữ dữ liệu thật (điện thoại, laptop Allianz):
nút ☁️ → Export → giữ file `screener-backup-*.json`. Đó là lưới an toàn duy nhất
không phụ thuộc Cloudflare.


## 2. Áp schema lên remote TRƯỚC, deploy SAU

Thứ tự này quan trọng: bản build mới GHI VÀO `kv_history` mỗi lần ghi đè. Nếu
deploy trước mà bảng đó chưa có trên remote thì mọi lần lưu đều lỗi.

    npx wrangler d1 execute screener-sync --file=./schema.sql --remote
    # CREATE TABLE IF NOT EXISTS — chạy lại nhiều lần vô hại

    # Kiểm ba bảng cứu hộ đã tồn tại:
    npx wrangler d1 execute screener-sync --remote --command \
      "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name;"

Phải thấy: kv, kv_history, kv_trash, scanner_kv, users.


## 3. Deploy bản đã sửa

    cd ../..
    npm run build --workspace @screener/core
    npm run build --workspace @screener/desktop
    cd apps/desktop
    npx wrangler pages deploy dist --project-name the-professional

Deploy TRƯỚC khi restore — restore xong mà client vẫn là bản cũ thì nó ghi đè
lại lần nữa.

Lưu ý: `wrangler pages deploy` chỉ thay site tĩnh + Functions. D1 và các secret
(`VITE_ACCESS_CODES`, `SCANNER_TOKEN`) còn nguyên, KHÔNG phải đặt lại.


## 4. Xem còn cứu được gì

    npx wrangler d1 execute screener-sync --remote --command \
      "SELECT archived_at, datetime(archived_at/1000,'unixepoch') AS luc,
              length(value) AS bytes
         FROM kv_history WHERE key='accounts' ORDER BY archived_at DESC LIMIT 20;"

    npx wrangler d1 execute screener-sync --remote --command \
      "SELECT deleted_at AS archived_at, datetime(deleted_at/1000,'unixepoch') AS luc,
              length(value) AS bytes
         FROM kv_trash WHERE key='accounts' ORDER BY deleted_at DESC LIMIT 20;"

Phải SELECT cả `archived_at` thô, không chỉ `datetime(...)`: con số thô mới là
thứ bước 5 cần, và nó không suy ra được từ giờ đọc được.

Kết quả trông như thế này:

    ┌───────────────┬─────────────────────┬───────┐
    │ archived_at   │ luc                 │ bytes │
    ├───────────────┼─────────────────────┼───────┤
    │ 1758801600000 │ 2026-09-25 12:00:00 │   412 │  ← bản rỗng đã ghi đè
    │ 1754582400000 │ 2026-08-07 16:00:00 │ 18734 │  ← BẢN CẦN CỨU (to nhất)
    └───────────────┴─────────────────────┴───────┘

Cột `bytes` là cách nhận ra bản đúng: bản có vị thế TO HƠN bản rỗng rất nhiều
(chục nghìn byte so với vài trăm). Chép nguyên con số `archived_at` 13 chữ số của
dòng đó — đó là `<so-archived_at>` của bước 5.

Không thích đọc bảng thì lấy bằng JSON, trường `archivedAt` nằm ngay trong đó:

    curl -s -H 'X-Sync-Code: <ma-sync>' \
      'https://the-professional.pages.dev/api/sync/history?key=accounts'
    # → {"versions":[{"key":"accounts","archivedAt":1754582400000,"bytes":18734,…}]}


## 5. Restore

ĐÓNG HẾT tab/app trên mọi thiết bị trước đã — sync là last-write-wins, một tab
còn mở sẽ đẩy bản rỗng đè lên bản vừa cứu.

Điền con số 13 chữ số lấy ở bước 4 vào `archivedAt` — ví dụ thật:

    curl -X POST https://the-professional.pages.dev/api/sync/restore \
      -H 'content-type: application/json' \
      -H 'X-Sync-Code: abc-ma-sync-that-cua-minh' \
      -d '{"key":"accounts","archivedAt":1754582400000}'

    # → {"ok":true,"key":"accounts","updatedAt":1758807…}

Ba cách điền sai và thông báo tương ứng:

    "archivedAt":"1754582400000"   → 400 need { key, archivedAt }   (chuỗi, không phải số)
    "archivedAt":1754582400         → 404 no such archived version   (giây, thiếu 3 số 0)
    lệch một chữ số                 → 404 no such archived version

Con số là một phần của KHÓA CHÍNH, nên nó phải khớp tuyệt đối — không làm tròn,
không cắt bớt. 404 nghĩa là số sai, KHÔNG phải mất dữ liệu: chạy lại bước 4.

Chưa có UI cho việc này nên `curl` là đường duy nhất. Bản thân restore cũng được
archive lại, nên bấm sai vẫn lùi được (bản vừa bị thay xuất hiện trong
`kv_history` với `archived_at` = đúng lúc restore).

Nếu laptop kia là Windows: chạy mấy dòng `curl` này trong **Git Bash**, đừng chạy
trong PowerShell. PowerShell không hiểu nháy đơn theo kiểu POSIX và `curl` ở đó là
alias của `Invoke-WebRequest` — kết quả là một lỗi cú pháp trông như lỗi server.
Bí quá thì dùng `curl.exe` và bọc JSON bằng nháy đôi đã escape.

Các key khác cũng restore được y như vậy nếu cần: `watchlists:index`,
`watchlist:*`, `post:*`. Liệt kê tất cả bản đã archive (bỏ `?key=`):

    curl -s -H 'X-Sync-Code: <ma-sync>' \
      'https://the-professional.pages.dev/api/sync/history'


## 6. Nếu `kv_history` rỗng

Nghĩa là lần mất dữ liệu xảy ra TRƯỚC khi bản có lưu lịch sử được deploy
(commit "Data Lost issue…", 2026-08-07). Lúc đó chỉ còn Time Travel của D1:

    npx wrangler d1 time-travel info screener-sync      # mốc xa nhất còn restore được
    npx wrangler d1 time-travel restore screener-sync --timestamp=<ISO-8601>

Hai điều cần biết trước khi bấm:
  - nó restore CẢ DATABASE (mọi bảng, mọi user, kể cả `scanner_kv`);
  - cửa sổ lưu trữ có hạn — lần mất dữ liệu khoảng tháng 8 có thể đã ngoài tầm.
    `time-travel info` trả lời dứt điểm.
Bước 1 đã có bản export nên vẫn lùi lại được nếu restore ra kết quả tệ hơn.


## 7. Xác nhận

Mở app, dán mã sync, kiểm số vị thế và vốn của TỪNG account. Rồi Export ngay một
bản nữa — từ giờ mỗi lần sửa account xong nên export một lần, đó là thứ duy nhất
không nằm trên Cloudflare.
