TASK: Build a TypeScript monorepo stock-screener app (rewrite of an existing Python project), architected so an iOS app can be added later with zero logic rewrite.

CONTEXT this is an existing stock screener written in Python (FastAPI + SQLAlchemy + pandas + yfinance, optional TA-Lib) with a web dashboard (HTML/CSS/JS using TradingView lightweight-charts). The OLD Python project is in this repo as the REFERENCE implementation. DO NOT modify it. Build the NEW project as a separate TypeScript monorepo.

The screener computes: ATR, EMA (5/10/21/50/150/200), volume dry-up, VCP contractions, Weinstein Stage 2, pivot proximity, and a 0-100 score producing signals: BREAKOUT_IMMINENT (score >= 70 and within 3% of pivot), CONSOLIDATING (score >= 40), NO_SIGNAL. Scoring weights: Stage 2 = 25, ATR contraction >= 30% = 20, price range < 5% = 15, volume dry-up >= 40% = 15, VCP contractions (3+) = 15, pivot proximity < 1% = 10.

FEATURE 3: PAPER TRADING — MULTI-ACCOUNT (in core, module portfolio)

Multiple independent Accounts, each to test a different strategy. Each Account: name, description, initialCapital (e.g. 50000), currency (EUR), createdAt, and its own trades. All cash/PnL/risk computed PER ACCOUNT, never mixed.
Buying: user enters X shares, price, and date manually. Store as BuyLots (ticker, buyDate, buyPrice, shares, remainingShares, entry signal/reason, optional stop, optional target). Multiple lots per ticker allowed.
Selling: user enters shares/price/date. Partial sells allowed; match against lots FIFO. The sold portion is realized (record realized PnL); the remainder keeps being tracked. Store SellRecords (ticker, matched lot, sellDate, sellPrice, shares, realizedPnL).
Cash = initialCapital - total bought + total sold (computed, never stored stale). Account equity = cash + market value of open positions.
Manual "Update" button: on click, pull latest (and any missed days') OHLC via DataProvider for all held tickers, recompute all metrics, append an EquitySnapshot (date, equity, cash, positionsValue) per account. No background jobs.
PER-POSITION METRICS: current market value, unrealized PnL (€ and %), realized PnL, distance to stop and to target, R-multiple (= PnL / initial per-share risk where risk = entry - stop), days held, optional MFE/MAE.

ACCOUNT / RISK METRICS: cash remaining, total equity, total PnL (€ and % vs initialCapital), unrealized vs realized PnL, per-position risk in € (= (entry - stop) * shares held) and as % of equity, total open risk (sum, as % of equity), max drawdown (from equity snapshots), win rate, average R-multiple, expectancy per trade, open vs closed trade counts, position concentration (% of account per ticker).

STOP-LOSS POLICY: stop is optional at buy time. If no stop is set, the position is created normally, its risk is treated as "undefined" and EXCLUDED from total risk, and the UI shows a reminder to set a stop. Once a stop is entered, risk is computed normally and the stop-loss order becomes active. User can edit the stop anytime (e.g. trailing it up); risk recalculates.

PENDING ORDERS (in core):

Order types: BUY_STOP (fill when price rises through a threshold), STOP_LOSS (attached to a held position, fill when price falls through threshold), optional TAKE_PROFIT. Each order has status pending|filled|cancelled.
Fill logic uses intraday High/Low, NOT just close: BUY_STOP fills when day High >= threshold, fill price = threshold; STOP_LOSS fills when day Low <= threshold, fill price = threshold. When the user clicks Update, scan EACH missed day in chronological order to detect fills (do not only check the latest day).
If a BUY_STOP would fill but cash is insufficient for the full ordered shares: DO NOT fill (no partial), mark the order accordingly, and notify the user with the reason (needed vs available cash and the date).
PER-ACCOUNT UI: an equity curve line chart (TradingView lightweight-charts) over time, optionally overlaid with the initial-capital baseline and optionally a benchmark; an account metrics panel (all account/risk metrics above); a list of open positions (with stop reminders) and closed-trade history. Plus a CROSS-ACCOUNT comparison view (side-by-side table: total return %, win rate, expectancy, max drawdown, etc.) to compare strategies.
